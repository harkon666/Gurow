# Domain documentation

Gurow uses one domain context across the frontend, editor engine, and backend.

Before exploring or changing domain behavior, read the root [CONTEXT.md](../../CONTEXT.md) and the relevant decisions in [the ADR directory](../adr/). Use the glossary's terms in specs, APIs, tests, and explanations. Surface a conflict with an ADR explicitly before proposing a replacement decision. If a referenced domain document is absent, proceed with the available context.

For engine or learning-domain implementation, also read the agreed [prototype sequence](../PROTOTYPE_PLAN.md) and [validation criteria](../ENGINE_VALIDATION_PLAN.md). These contain planned gates; only recorded implementation and test evidence establishes that a gate has passed.

Record agreed vocabulary and invariants in the glossary. Record decisions with meaningful trade-offs in ADRs. Keep implementation plans and test reports separate from the glossary.
