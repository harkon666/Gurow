# Scope coach-mode XP to Enrollments

Access thresholds in coach mode use only XP from the relevant Enrollment. XP earned in personal mode or other Enrollments is excluded, keeping each coach's thresholds scoped to the Learning Path and version the learner joined. Learners therefore maintain separate XP totals for their Enrollments and cannot automatically carry XP from other learning contexts into a new Enrollment's access checks.

For MVP coach mode, a Task receiving valid Approval grants XP in the amount set by the coach; multiple approved revisions of the same Task never multiply its reward within an Enrollment. This ties rewards to reviewed work and prevents repeated revisions from multiplying the Task's reward, at the cost of learners waiting for review and receiving no additional XP for further improvements to an already approved Task.

A Task's XP contribution to an Enrollment remains at its configured reward while at least one submitted revision within that Enrollment has a valid Approval, and is zero otherwise. Revoking its last valid Approval automatically removes that reward through a recorded correction; a later valid Approval restores the same reward through another recorded correction without multiplying it. This keeps XP supported by valid assessment while allowing an Enrollment's total XP to decrease after a coach corrects an Approval.

XP Thresholds use current Enrollment XP even after a Skill has been opened or started, so a drop below the threshold locks that Skill again unless an active Access Override applies. An authorized coach may grant this exception for one Skill within one Enrollment, waiving both Prerequisites and the XP Threshold without changing XP or Mastery; granting or revoking it requires a recorded reason as described in [the Access decision](0001-separate-access-from-mastery.md). Submissions sent while Access was valid remain eligible for review, and Mastery supported by valid evidence remains in force. This keeps access requirements current while allowing explicit coach exceptions, but an XP correction for one Task can still block new submissions on other Skills without an applicable override within the same Enrollment.
