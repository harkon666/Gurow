# Keep a Coach's preparation board with its Draft

[ADR 0027](0027-separate-task-board-organization-from-assessment.md) gives a Coach's Learning Path Draft its own Task Boards for material readiness, and [ADR 0028](0028-save-task-boards-whole-against-their-own-revision.md) sets how a personal board is stored and saved. This decision applies the same contract to a Draft Skill's preparation board and sets what it belongs to.

A preparation board belongs to one Draft (the Path's unpublished Version) and one of its Skills. It is stored apart from the Draft's content, with its own revision, and saved whole against that revision exactly like a personal board: the server checks that every Task of the Skill in this Draft is on exactly one card, a stale save changes nothing and answers the current board, and repeating the accepted arrangement is a retry that changes nothing again. Its first opening creates Ideas, In preparation and Ready and places the Draft's Tasks in Ideas in their saved order. No column has a role: there is no Completion Column, a board with one is refused, and a save writes nothing but the board. Ready is a name the Coach may change; publication checks only the Draft's progression rules ([ADR 0008](0008-validate-required-progression-before-publication.md)).

The route names the Draft as well as the Path and Skill, and only the Path's owning Coach reaches it. A request for a Draft that was published meanwhile is refused rather than redirected to the next Draft. The Draft's other entry points keep an opened board coherent in their own transactions and advance its revision: a Draft save adds a card for a new or copied Task at the end of the first column and removes the card of a deleted Task, deleting a Skill deletes its board, and archiving a published Task removes its card before the Task leaves the Draft. A card refers to the Task's definition in the Draft, so the database refuses a card for a Task the Draft no longer holds.

Publishing freezes the board with the Version: its rows fall under the same immutability trigger as the Version's content, and board writes serialize with a publication under the Path lock. The next Draft starts its own board from its Tasks rather than inheriting the previous Draft's columns, so readiness is never carried forward as if it were progress, and nothing of a board reaches a learner's enrolled Version.

Keeping the board with the Draft was chosen over one board per Path and Skill across Drafts because it keeps published Versions, and everything attached to them, immutable, and makes "this Draft's preparation" the only thing a board can describe. The cost is that a Coach who customized columns re-creates them for the next Draft.
