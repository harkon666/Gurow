# Archive Tasks as revision-checked actions, and keep Skills with history

[ADR 0018](0018-archive-content-with-learning-history.md) archives content that has progress history instead of deleting it. This decision sets what can be archived in the MVP, how archival reaches the editor, and what counts as history.

Only Tasks are archived. In a personal Path, an archived Task leaves the editable document and active use, while its completion, contribution, XP history and its Skill's Mastery stay, so XP Thresholds still count it; the Skill shows it as retained history. In coach mode, a Task that a published Version holds is archived from the open Draft: the next Version leaves it out, and every published Version holding it, with its Enrollments' Submissions, Reviews, XP and Mastery, stays as it is. A Task only the Draft holds has no history to keep and is not archived. There is no restoration. A Skill with history is never deleted and is not archived either: archiving a Skill would need a policy for the Prerequisites that name it, which is not decided.

Archival is its own action, not a document save that leaves the Task out. It is based on the revision the owner saw and advances the Path's revision, because the editable document changes; the editor offers it only while its document is saved and then shows the document the backend answers. Another tab still on the old revision therefore gets an ordinary stale-save conflict, and reapplying its kept work ([ADR 0024](0024-reapply-kept-editor-work-as-a-new-save.md)) does not bring the archived Task back. A save that leaves out content with history is refused and names archival instead; leaving out unused content stays unsupported until deletion is implemented.

History is what the backend can see: a personal Task that was started, completed, ever had a recorded contribution or is archived; a personal Skill with such a Task, a Mastery declaration or withdrawal, or an Access Override; and in coach mode, anything a published Version holds, since that Version is the learning contract its Enrollments' records refer to.

Keeping archival a separate action costs an extra request and a reload of the editor's document, but leaves the save path unable to remove content with history by accident. Treating every published Task as history is broader than checking for Submissions, at the cost of refusing to delete published content no learner has touched yet, which a new Version can still leave out by archival.
