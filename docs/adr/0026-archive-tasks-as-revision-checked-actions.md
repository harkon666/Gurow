# Archive Tasks and disconnected Skills as revision-checked actions

[ADR 0018](0018-archive-content-with-learning-history.md) archives content that has progress history instead of deleting it. This decision sets what can be archived, how archival reaches the editor, and what counts as history. The original Task-only scope is extended on 2026-10-08 by the agreed disconnect-first policy for Skill archival.

In a personal Path, an archived Task leaves the editable document and active use, while its completion, contribution, XP history and its Skill's Mastery stay, so XP Thresholds still count it; the Skill shows it as retained history. In coach mode, a Task that a published Version holds is archived from the open Draft: the next Version leaves it out, and every published Version holding it, with its Enrollments' Submissions, Reviews, XP and Mastery, stays as it is. A Task only the Draft holds has no history to keep and is not archived through the Task archival action. There is no restoration.

A Skill may be archived only when it has no incoming or outgoing Prerequisite connections. Both the UI and backend refuse connected Skills; the owner must disconnect the connections explicitly and save those changes first. Archival never silently removes or rewires requirements. This deliberately makes removal less convenient rather than unexpectedly changing other Skills' Access.

A personal Skill's archival removes its card and active definition from the editable document, archives its active Tasks, and retains its stored definition, Task records, completion, XP, Mastery and history. It supports Skills with no active Tasks, including Skills whose only history is a Mastery or Access Override event. In coach mode, archival retains an immutable snapshot of the Skill and its current Draft Tasks, and removes only their open-Draft definitions, layout and preparation board. Existing published Versions and Enrollments are unchanged; the next Version excludes the archived Skill. Disconnected Skills can be archived even without history; deletion remains a separate action for unused content.

Archival is its own action, not a document save that leaves content out. It is based on the revision the owner saw and advances the Path's revision, because the editable document changes; the editor offers it only while its document is saved and then shows the document the backend answers. Another tab still on the old revision therefore gets an ordinary stale-save conflict, and reapplying its kept work ([ADR 0024](0024-reapply-kept-editor-work-as-a-new-save.md)) does not bring archived content back. Ordinary saves cannot overwrite or reintroduce archived identities. Archived personal Skills and Tasks reject learning and board mutations. A save that leaves out content with history is refused and names archival instead; unused content can be removed through deletion.

History is what the backend can see: a personal Task that was started, completed, ever had a recorded contribution or is archived; a personal Skill that is archived, has such a Task, a Mastery declaration or withdrawal, or an Access Override; and in coach mode, anything a published Version holds, since that Version is the learning contract its Enrollments' records refer to. Retained Coach Skill snapshots reserve their logical identities even when never published.

Archived Skills are listed read-only outside the active canvas. Personal learning history remains readable there; published Coach learning records remain under their original Versions and visibility rules. There is no Restore or permanent-delete action for archived Skills.

Keeping archival a separate action costs an extra request and a reload of the editor's document, but leaves the save path unable to remove content with history by accident. Treating every published Task as history is broader than checking for Submissions, at the cost of refusing to delete published content no learner has touched yet, which a new Version can still leave out by archival.
